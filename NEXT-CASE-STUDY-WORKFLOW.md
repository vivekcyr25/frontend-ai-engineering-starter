# How to Add the Next Case Study

Use this process to add a new project to the existing portfolio without changing its design system or weakening its evidence standards.

> Do not create a new page type unless the existing portfolio structure genuinely cannot support the case.

## Step 1 — Create the case-study draft

1. Add a new project entry to the existing portfolio project structure and route it through the same Work / Case Studies pattern as the current cases.
2. Start with the established direct, technical, practical, and honest voice. The purpose is to help an engineering manager inspect real work, not to write marketing copy.
3. Reuse the existing typography, colors, spacing, cards, CTA patterns, image treatment, and navigation. Do not change global styles unless the evidence genuinely needs a supported treatment that does not already exist.
4. Create the draft with only the three required beats below. Unknown information stays marked as `[TO BE COLLECTED WHEN COMPLETE]`.

## Step 2 — Gather evidence

Before making outcome claims, collect and verify:

- real screenshots of the finished project or relevant workflow;
- the GitHub repository link;
- a live demo/deployment link, if one exists;
- before/after evidence where it is relevant;
- an architecture or technical diagram where it improves understanding;
- verified metrics or results, including the baseline and measurement method;
- implementation details, code paths, test output, and decision notes;
- known limitations and incomplete work.

Do not substitute decorative generated images for project evidence. Keep the source file, URL, or command that supports every publishable claim.

## Step 3 — Write the three beats

### The Problem

Explain the actual problem, its context, and why it mattered. Do not describe a future goal as a completed problem solved.

### What I Did

State the personal contribution first. Then explain the implementation, technical decisions, trade-offs, AI-assisted development steps, and manual verification. Name only tools and technologies actually used.

### What Came of It

State only verified outcomes and point to evidence. Include remaining limitations. If the work is ongoing, use `[TO BE COLLECTED WHEN COMPLETE]` instead of guessing at an outcome, metric, or impact.

## Step 4 — Add supporting content

Add the case-study details using the existing evidence-card and case-study conventions:

- relevant technologies;
- real screenshots, diagrams, and evidence captions;
- GitHub repository link;
- demo link, only if verified and available;
- technical implementation explanation;
- limitations and verification boundaries.

Use descriptive alt text and captions that say what an image proves. Keep links explicit and do not publish placeholder URLs.

## Step 5 — Review

Before publishing, confirm:

- every technical claim is true and explainable;
- no metric was fabricated or copied from an unverified source;
- no technology was added merely because it sounds relevant;
- the personal contribution is clear and distinct from the wider system;
- the case-study voice matches the portfolio voice card;
- images are real project evidence where possible;
- the limitations are visible rather than hidden;
- all repository and demo links open successfully.

## Step 6 — Publish

1. Test the page locally.
2. Run the project build and resolve errors.
3. Check the page at mobile and desktop widths.
4. Check image loading, captions, navigation, CTA targets, and external links.
5. Commit only the intended case-study, assets, and supporting documentation changes with a Conventional Commit message.
6. Deploy through the existing portfolio deployment process.
7. Open the live case-study page and recheck its responsive layout, evidence, and links.

## Step 7 — Preserve consistency

Compare the completed case with the established portfolio before merging or publishing:

- fonts;
- colors;
- spacing;
- card styles;
- CTA style;
- image treatment;
- navigation;
- direct, evidence-first case-study voice.

The new case should feel like the next proof item in the same portfolio, not a mini-site with a new visual language.
